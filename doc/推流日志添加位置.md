## 零、关键修复：摄像头推流编码器选择（2026-05-04）

### 问题
`pushCameraPreviewLoop` 原本使用 `avcodec_find_encoder(AV_CODEC_ID_H264)` 直接取 FFmpeg 默认编码器，
忽略了用户在 UI 中选择的编码器偏好（nvenc/amf/cpu），且失败后不做回退。

### 修复内容

**service.cpp** — Camera 场景 params 中新增 `encoder=` 参数：
```cpp
if (!options.videoEncoder.trimmed().isEmpty())
{
    params << QStringLiteral("encoder=%1").arg(options.videoEncoder.trimmed());
}
```

**streamffmpeg.cpp** — `pushCameraPreviewLoop` 编码器选择逻辑替换为回退链：
1. 使用 `pickVideoEncoderCandidates(params.videoEncoder)` 获取候选列表
2. 按顺序尝试每个编码器（nvenc → amf → libx264，或按用户指定）
3. 每个编码器打开失败时记录 `[摄像头预览推流] 编码器打开失败，<name>: <error>`
4. 全部失败则报 `所有备选编码器均无法打开`
5. 成功则日志显示 `编码器已打开: <name>`

编码器参数也做了区分：
- NVENC: preset=p1, tune=ll, rc=cbr, zerolatency=1
- AMF: 不设额外参数（避免选项解析失败）
- 其他 H264: preset=superfast, tune=zerolatency

## 七、日志解读指南

当摄像头模式推流失败时，观察日志最后停在哪个阶段：

| 最后一条日志 | 含义 | 可能原因 |
|-------------|------|----------|
| `[推流] Camera(preview): device=...` 后无日志 | startPush 返回 false | 输入/输出地址为空，或 startPushWorkerByRoute 失败 |
| `[推流路由] kind=4 ...` 后无日志 | 路由解析后失败 | CameraCapture 路由的 device 参数为空 |
| `[推流启动] 路由=4 ...` 后无 `FLV输出上下文创建成功` | 输出上下文创建前失败 | 音频设备打开异常导致提前退出 |
| `FLV输出上下文创建成功` 后无 `首帧就绪` | CameraFrameBus 无帧 | 摄像头未播放、Qt6后端不发布到Bus、预览已暂停 |
| `首帧就绪` 后无 `编码器已打开` | 编码器未找到或打开失败 | H264/MPEG4编码器不可用 |
| `编码器已打开` 后无 `输出已打开` | avio_open2 失败 | RTMP 地址不可达、网络不通 |
| `输出已打开` 后无 `FLV头已写入` | avformat_write_header 失败 | RTMP 服务端拒绝连接 |
| `FLV头已写入` 后无 `发包统计` | 主循环中编码/写包失败 | 分辨率变化、音频写包错误 |
| `退出: exitCode=...` | 正常退出 | exitCode=0 正常停止，非0为错误 |
