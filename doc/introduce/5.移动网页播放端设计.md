# 移动/网页播放端设计

## 第一部分：功能模块设计

### 1. 模块总览

移动/网页播放端是 FPlayer 系统的流媒体消费者，由两个项目组成：

- **fplayer-ff-mobile**：基于 Flutter 的跨平台移动播放器，支持 Android、Windows、Web 平台
- **FPlayer-WebSite**：产品展示网站，用于系统功能展示和推广

```
┌──────────────────────────────────────────────────────┐
│               移动/网页播放端功能模块                    │
├────────────┬────────────┬────────────┬──────────────┤
│ 流媒体播放 │ 播放地址   │ 设置持久化  │ UI 主题      │
│ 模块       │ 解析模块   │ 模块       │ 管理模块     │
├────────────┼────────────┼────────────┼──────────────┤
│ 日志调试   │ 播放控制   │ 产品展示   │              │
│ 模块       │ 模块       │ 模块(Web)  │              │
└────────────┴────────────┴────────────┴──────────────┘
```

### 2. 流媒体播放模块

**功能描述**：支持多种流媒体协议的播放，核心基于 media_kit（libmpv 封装）。

**支持的协议**：

| 协议 | Android | Windows | Web | 延迟 |
|------|---------|---------|-----|------|
| HLS | 原生支持 | 原生支持 | 优先推荐 | 5-15s |
| HTTP-FLV | 有限支持 | 原生支持 | 不推荐 | 1-3s |
| RTMP | 有限支持 | 原生支持 | 不支持 | 1-3s |

**协议自动选择**：
- Web 平台默认选择 HLS（FLV/RTMP 在浏览器环境渲染受限）
- Android 平台默认选择 HLS（FLV/RTMP 兼容性问题）
- Windows/Desktop 平台默认选择 HTTP-FLV（低延迟优势）

**播放器初始化**：
```dart
final player = Player();                    // media_kit 核心播放器
final controller = VideoController(player); // 视频控制器
```

**播放器生命周期**：
- `player.open(Media(url), play: true)` — 打开流并自动播放
- `player.stop()` + `player.pause()` — 停止播放
- 状态流监听：`playing`、`buffering`、`completed` 状态变化记录到日志

### 3. 播放地址解析模块

**功能描述**：支持两种方式获取播放地址——服务地址模式（自动解析）和直连模式（手动输入）。

#### 3.1 服务地址模式

移动端通过调用 Gateway 的解析 API 自动获取播放地址：

```
用户输入: Gateway URL + app + stream
       │
       ▼
GET {gatewayUrl}/api/v1/streams/resolve?app={app}&stream={stream}
       │
       ▼
解析 JSON 响应，提取对应协议的播放 URL:
  - playHls        → HLS 地址
  - playHttpFlv    → HTTP-FLV 地址
  - playUrls.rtmp  → RTMP 地址
```

这种模式的优势：
- 用户无需知道动态端口，只需 app 和 stream 名称
- 服务端端口变化时无需更新客户端配置
- 支持公网代理模式，内外网自动切换

#### 3.2 直连模式

直接输入完整的流 URL，适用于：
- P2P 直连场景（不经过服务端）
- 测试调试场景
- 非 FPlayer 体系的第三方流

### 4. 输入模式切换

用户可在两种输入模式之间切换：

**服务模式 UI**：
- Gateway URL 输入框（默认 `http://192.168.1.100:9000`）
- App 名称输入框（默认 `live`）
- Stream 名称输入框（默认 `stream001`）
- 协议选择下拉框（HLS / HTTP-FLV / RTMP）

**直连模式 UI**：
- URL 输入框（直接输入完整流地址）

模式切换通过 `AnimatedSize` 实现卡片式的平滑展开/收起动画。

### 5. 播放控制模块

**功能描述**：提供适合直播场景的播放控制界面。

**控制项**：
- **播放/暂停按钮**：启动和暂停流播放，带 `AnimatedSwitcher` 过渡动画
- **停止按钮**：完全停止播放并重置状态
- **音量控制**：系统音量调节
- **全屏按钮**：进入全屏播放模式

**直播优化**：
- 隐藏进度条（直播流无时长概念）
- 禁用拖动快进手势
- 禁用双击快进
- 仅保留播放/暂停、音量、全屏三个必要控件

控件配置通过 media_kit 的 `MaterialDesktopVideoControlsTheme` 和 `MaterialVideoControlsTheme` 实现。

### 6. 日志调试模块

**功能描述**：内置的日志面板，用于排查播放问题。

**日志分类**：
- **INFO**：播放状态变化（开始播放、停止、完成）
- **WARN**：平台兼容性警告（如在 Web 平台选择 FLV/RTMP）
- **ERROR**：播放错误（网络错误、解析失败）

**日志功能**：
- 最多保留 200 条日志，超出后自动移除旧条目
- 自动滚动到最新日志
- 分类计数徽章（`_LogCountBadge`），显示各级别日志数量
- 复制全部日志到剪贴板
- 一键清空日志

### 7. 设置持久化模块

**功能描述**：通过 `shared_preferences` 持久化用户配置，应用重启后恢复上次设置。

**持久化项目**：
- 主题模式（system / light / dark）
- 输入模式（service / direct）
- Gateway URL
- App 名称
- Stream 名称
- 选择的协议
- 直连 URL

**保存机制**：每个输入框绑定 `addListener`，内容变化时自动保存，无需手动保存按钮。

### 8. UI 主题管理模块

**功能描述**：支持 Material 3 主题系统，提供三种主题模式。

**主题模式**：
- **跟随系统**：根据系统深色模式自动切换
- **浅色模式**：亮色背景、深色文字
- **深色模式**：深色背景（`#17171C`）、浅色文字

**配色方案**：
- 主色：蓝色（`#1863DC`）
- 表单焦点色：紫色（`#9B60AA`）
- 深色背景：近黑色（`#17171C`）
- 错误色：Material 标准红色

**切换方式**：AppBar 右侧的调色板图标按钮，点击循环切换三种模式。

### 9. 产品展示模块（FPlayer-WebSite）

**功能描述**：静态产品展示页面，用于介绍 FPlayer 系统的功能和应用场景。

**页面结构**：
- Hero 区域：产品名称与核心描述
- 产品演示区：桌面客户端截图轮播与图片灯箱（点击放大、键盘导航）
- 功能亮点区：四个关键特性卡片
- 应用场景区：工业视觉、医疗影像、智慧教育、本地化办公
- 三端介绍区：Desktop + Service + Mobile 功能说明
- 页脚：版权信息与技术栈

**技术特点**：
- 单文件静态页面（HTML + 内联 CSS + 内联 JS）
- 无构建系统、无 npm 依赖、无 API 调用
- Tailwind CSS CDN + 自定义样式覆盖
- AOS（Animate On Scroll）滚动动画
- 自研图片灯箱（支持前后切换、键盘导航、ESC 关闭）

## 第二部分：技术选型

### 1. 技术栈概览

| 组件 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| 移动框架 | Flutter | 3.3+ SDK | 跨平台 UI、单代码库、Material 3 |
| 媒体播放 | media_kit | 1.1.11 | libmpv 的 Dart 封装，全协议支持 |
| 视频渲染 | media_kit_video | 1.2.5 | Flutter Widget 视频渲染 |
| 原生库 | media_kit_libs_video | 1.0.5 | 预编译 libmpv + FFmpeg 库 |
| HTTP 客户端 | http | 1.2.2 | 调用 Gateway 解析 API |
| 本地存储 | shared_preferences | 2.3.4 | 键值对持久化 |
| 网页技术 | HTML + CSS + JS | — | 单文件静态页面 |
| CSS 框架 | Tailwind CSS | CDN | 原子化 CSS 工具类 |
| 动画库 | AOS | 2.3.1 | 滚动触发动画 |

### 2. 选型分析

#### 2.1 为什么选择 Flutter

- **跨平台**：一套代码同时编译 Android APK/AAB、Windows EXE 和 Web 应用
- **性能**：Skia 渲染引擎直接绘制，非 WebView 方案，视频渲染性能好
- **UI 表现力**：Material 3 设计系统，`AnimatedSwitcher`/`AnimatedSize` 等内置动画组件
- **生态成熟**：media_kit、shared_preferences 等关键依赖成熟稳定
- **无平台代码**：本项目零自定义 Platform Channel，纯 Dart 实现

#### 2.2 为什么选择 media_kit

- **libmpv 封装**：mpv 是业界最强大的开源播放器内核，支持几乎所有流媒体协议
- **多协议支持**：HLS/HTTP-FLV/RTMP 开箱即用，无需额外适配
- **多平台原生库**：`media_kit_libs_video` 提供 Android/Windows/Linux 的预编译 libmpv + FFmpeg 库
- **Flutter 集成**：`media_kit_video` 提供 Flutter Widget 级别的视频渲染组件

#### 2.3 为什么选择 shared_preferences

- **轻量**：键值对存储，适合少量配置数据的持久化
- **无 Schema**：不需要定义数据库结构或迁移
- **Flutter 官方推荐**：对于简单配置，flutter.dev 推荐使用 shared_preferences

#### 2.4 为什么网页端选择静态 HTML

- **产品展示定位**：网页端的功能是展示和推广，而非流媒体播放
- **零部署成本**：单个 HTML 文件，可直接部署到任何静态文件服务器或 GitHub Pages
- **CDN 依赖外置**：Tailwind CSS 和 AOS 通过 CDN 加载，页面本体极小

### 2. 状态管理

移动端未使用外部状态管理库（如 Provider、Riverpod、Bloc），而是采用 Flutter 原生的 `setState()` 模式：

```dart
// 关键状态变量
bool _isLoading = false;        // 加载中
bool _isStreaming = false;      // 正在播放
String? _errorMessage;          // 错误信息
List<LogEntry> _logs = [];     // 日志列表

// 输入模式
UrlInputMode _inputMode;           // service / direct
ServicePlayProtocol _protocol;     // hls / httpFlv / rtmp
```

这种简单的状态管理对于单页面的播放器应用是足够的，避免了引入重型状态管理框架的复杂性。

### 4. Gateway API 集成

```dart
Future<String?> _resolvePlayUrlFromGateway() async {
    // 1. 构建请求 URL
    var url = '${_gatewayUrl}/api/v1/streams/resolve'
              '?app=${_appController.text}'
              '&stream=${_streamController.text}';
    
    // 2. 发起 HTTP GET 请求
    final response = await http.get(Uri.parse(url), headers: {
        'Accept': 'application/json',
    });
    
    // 3. 解析响应
    final data = jsonDecode(response.body);
    
    // 4. 提取对应协议的播放 URL
    switch (_protocol) {
        case ServicePlayProtocol.hls:
            return data['playHls'] ?? data['playUrls']?['hls'];
        case ServicePlayProtocol.httpFlv:
            return data['playHttpFlv'] ?? data['playUrls']?['httpFlv'];
        case ServicePlayProtocol.rtmp:
            return data['playUrls']?['rtmp'];
    }
}
```

### 7. 项目的极简设计理念

移动端项目体现了极简设计哲学：

- **单文件架构**：全部代码在 1431 行的 `main.dart` 中，无多层目录结构
- **零自定义平台代码**：Android `MainActivity.kt` 是 Flutter 默认生成，无任何自定义逻辑
- **零状态管理库**：使用 `setState()` 而非 Provider/Riverpod/Bloc
- **零外部 API 认证**：Gateway API 无认证层，内网环境开箱即用
- **最小依赖**：仅 5 个核心依赖（http、shared_preferences、media_kit 三件套）

### 9. 未来扩展方向

- **iOS 平台支持**：目前项目未包含 iOS 目标，可通过添加 Runner 工程和 media_kit 的 iOS 库支持实现
- **状态管理升级**：若功能持续增长，可引入 Riverpod 管理状态
- **多流同时播放**：支持多路流的多窗口或画中画播放
- **推流能力**：通过 FFmpeg 原生集成，移动端也可实现采集推流
