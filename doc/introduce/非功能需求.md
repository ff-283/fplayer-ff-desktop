# 非功能需求

## 1. 性能需求

端到端推流延迟控制在两秒以内（HTTP-FLV），HLS 因切片机制放宽至八秒。Gateway API 的 P99 响应不超过一百毫秒。服务端需支撑至少五十路并发推流和单路百级并发拉流。资源占用方面，服务端空闲内存不超过五百兆，桌面端 1080p@30fps 硬编推流时 CPU 不超过百分之三十，帧率保持率不低于百分之九十五。

## 2. 可靠性需求

服务端需稳定运行七十二小时以上。启动时端口冲突自动切换重试。子进程异常退出须输出明确错误信息而非静默失败。runtime.json 采用原子写入防止读到半写数据。桌面端网络中断后自动重连。

## 3. 安全与兼容性

系统默认纯局域网运行，不向公网发数据。API Key 密码框隐藏，日志不记录明文凭据。当前不做强制鉴权，架构预留 Token 扩展点。服务端兼容 Windows 10+ 和 Ubuntu 20.04+，移动端兼容 Android 7.0+、Windows 和 Web。编码器优先硬编（NVENC/QSV/AMF），保留 x264 软编回退。

## 4. 易用性与可维护性

核心操作三步以内完成。错误信息统一中文三段式。支持深色和浅色主题。桌面端采用 App → Widget → Service → Runtime → Backend → API 六层分层架构，接口与实现分离。服务端 Go 代码仅使用标准库，零第三方依赖。一键构建附带 SHA256 校验，所有依赖使用 MIT/BSD/LGPL 宽松许可证。
