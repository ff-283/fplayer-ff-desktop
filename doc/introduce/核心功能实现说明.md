# 核心功能实现说明

## 1. 多源采集

系统支持摄像头、屏幕和文件三种输入源，每种通过 API 层纯虚接口（ICamera / IScreenCapture / IPlayer）定义能力，由不同后端实现并通过 Runtime 工厂层统一创建。

摄像头采集的 FFmpeg 后端在 Windows 上通过 DirectShow COM API 枚举设备。先调用 CoCreateInstance 获取 ICreateDevEnum 系统设备枚举器，再通过 CreateClassEnumerator 传入 CLSID_VideoInputDeviceCategory 创建视频输入设备枚举器。遍历 IMoniker 列表，通过 IPropertyBag 读取设备 FriendlyName，通过 IAMStreamConfig::GetStreamCaps 逐一读取每个设备支持的分辨率和帧率组合，按格式字符串去重后生成候选列表。Linux 上则使用 FFmpeg 的 v4l2 输入格式和 avdevice_list_input_sources 函数获取设备列表，搭配预设的常用格式。设备选择时构建平台特定的输入 URL（Windows 为 "video=设备名" + dshow 格式，Linux 为 /dev/video 路径 + v4l2 格式），设置 probesize=32KB、max_analyze_duration=200ms 的探测参数，并注册中断回调函数使切换设备时可快速打断阻塞的 av_read_frame。采集循环在独立 QThread 中运行，核心流程为 av_read_frame → avcodec_send_packet → avcodec_receive_frame → SwsContext 转为 YUV420P → 深拷贝帧数据后通过跨线程信号发送给 OpenGL 预览控件，同时发布到 CameraFrameBus 供推流管道消费。

```cpp

{
```

```cpp
// 摄像头采集循环 — YUV420P 转换与帧总线发布（cameraffmpeg.cpp 节选）
while (m_impl->isCapturing.load()) {
    int ret = av_read_frame(m_impl->formatContext, packet);
    if (packet->stream_index == m_impl->stream->index) {
        avcodec_send_packet(m_impl->codecContext, packet);
        while (avcodec_receive_frame(m_impl->codecContext, frame) >= 0) {
            // 非 YUV420P 格式通过 SwsContext 统一转换
            if (frame->format != AV_PIX_FMT_YUV420P) {
                sws_scale(m_impl->swsContext, frame->data, frame->linesize,
                          0, frame->height,
                          m_impl->swsFrame->data, m_impl->swsFrame->linesize);
                renderFrame = m_impl->swsFrame;
            }
            // 深拷贝后跨线程发射，避免 AVFrame unref 后数据失效
            QByteArray yBuffer(reinterpret_cast<const char*>(renderFrame->data[0]), yStride * height);
            emit yuvFrameReady(yBuffer, uBuffer, vBuffer, width, height, yStride, uStride, vStride);
            CameraFrameBus::instance().publish(yBuffer, uBuffer, vBuffer, width, height,
                                               yStride, uStride, vStride, m_impl->frameBusSourceId);
        }
    }
}
```

屏幕捕获的 DXGI 后端性能最优。它通过 CreateDXGIFactory1 枚举 DXGI 适配器和输出，获取每个显示器的原生坐标和尺寸。打开 Duplication 时遍历适配器输出，按坐标容差（±2px）匹配目标屏幕，调用 D3D11CreateDevice 创建 D3D11 设备，再通过 IDXGIOutput1::DuplicateOutput 获取桌面复制接口。每帧采集时，AcquireNextFrame 获取当前桌面纹理，QueryInterface 拿到 ID3D11Texture2D，CopyResource 拷贝到 CPU 可读的暂存纹理，Map 读取 BGRA 数据。随后通过两个独立的 SwsContext 分别转换：预览链路固定使用屏幕原始尺寸的 YUV420P 发送给 OpenGL 控件，推流链路按 ScreenFrameBus 发布的目标尺寸缩放。遇到 DXGI_ERROR_ACCESS_LOST 时自动释放资源、休眠 80ms 后重建 Duplication，实现无人值守恢复。光标叠加通过 GDI 的 GetCursorInfo + DrawIconEx 在 BGRA 帧上完成。

```cpp
// DXGI 屏幕捕获 — Duplication 创建与单帧捕获（screencapturedxgi.cpp 节选）
// 打开 Duplication
D3D11CreateDevice(adapter, D3D_DRIVER_TYPE_UNKNOWN, nullptr,
    D3D11_CREATE_DEVICE_BGRA_SUPPORT, levels, nlevels, D3D11_SDK_VERSION,
    &device, &fl, &context);
IDXGIOutput1* out1 = nullptr;
output->QueryInterface(IID_PPV_ARGS(&out1));
out1->DuplicateOutput(device, &dupl);  // 获取桌面复制接口

// 单帧捕获
IDXGIResource* desktopRes = nullptr;
DXGI_OUTDUPL_FRAME_INFO fi{};
dupl->AcquireNextFrame(100, &fi, &desktopRes);   // 100ms 超时
ID3D11Texture2D* acquired = nullptr;
desktopRes->QueryInterface(IID_PPV_ARGS(&acquired));
ctx->CopyResource(staging, acquired);             // GPU→CPU 暂存纹理
ctx->Map(staging, 0, D3D11_MAP_READ, 0, &map);  // 读取像素数据
// BGRA→YUV420P 转换
sws_scale(swsPreview, srcSlice, srcStrideArr, 0, th, previewYuv, previewStride);
dispatchFrameToView(m_previewY, m_previewU, m_previewV, ...);
ScreenFrameBus::instance().publish(m_pushY, m_pushU, m_pushV, ...);
```

文件播放的 FFmpeg 后端实现了完整的三线程架构。解复用线程循环 av_read_frame 并将音视频包分发到独立队列（视频上限 120 包，音频上限 240 包）。解码线程消费视频包，解码后经 SwsContext 转为 YUV420P，以音频时钟为基准做音视频同步——视频超前 40ms 则休眠，落后 80ms 则丢帧，无音频时使用壁钟基准。解码帧同时发送到 OpenGL 预览和 ScreenFrameBus（当设置了合成流总线 ID 时）。音频线程独立运行，解码后经 SwrContext 重采样为 S16 立体声 48kHz 通过 QAudioSink 播放。

## 2. 实时画布合成

画布合成系统基于 QMdiArea 多文档界面实现，每个视频源是一个 ComposeSourceItem，包含 sourceId（帧总线通道键）、subWindow（QMdiSubWindow 定位容器）和 container（ComposeSourceWidget，支持八向拖拽调整大小和移动）。画布由 AspectRatioHostWidget 约束宽高比，内容居中并按宿主尺寸等比缩放。素材 Z 顺序由列表位置决定，400ms 的守护定时器在拖拽停止后强制执行正确的层叠。

合成模式下所有源的 YUV420P 帧通过 CameraFrameBus 和 ScreenFrameBus 两个线程安全单例总线汇集。帧总线以源 ID 为键管理通道，提供 publish/snapshot 接口，ScreenFrameBus 还增加了 snapshotIfNew（仅当序列号更新时返回帧）和 publishTargetSize（供消费者设定推流目标尺寸，生产者据此缩放）。快照合成时创建 QImage 画布，遍历素材列表，从对应帧总线快照 YUV 帧，经 i420ToImage 转 RGB 后，按子窗口几何与视口几何的比例计算目标矩形，在矩形内按宽高比居中绘制。

```cpp
// 合成快照 — 帧总线汇集 + 按比例绘制（capturewindow.cpp 节选）
QImage CaptureWindow::buildComposeSnapshotImage(const QSize& outSize) const {
    QImage canvas(outSize, QImage::Format_RGB888);
    canvas.fill(Qt::black);
    QPainter painter(&canvas);
    for (const auto& src : m_composeSources) {
        QImage srcImage;
        if (src.kind == ComposeSourceItem::SourceKind::Camera) {
            const auto frame = CameraFrameBus::instance().snapshot(src.sourceId);
            if (frame.valid) srcImage = i420ToImage(frame.y, frame.u, frame.v, ...);
        } else {
            const auto frame = ScreenFrameBus::instance().snapshot(src.sourceId);
            if (frame.valid) srcImage = i420ToImage(frame.y, frame.u, frame.v, ...);
        }
        // 将子窗口几何按视口→画布比例映射到目标矩形
        const QRect g = src.subWindow->geometry();
        const QRect target(
            qRound((double(g.x()) / srcBounds.width()) * outSize.width()),
            qRound((double(g.y()) / srcBounds.height()) * outSize.height()),
            qRound((double(g.width()) / srcBounds.width()) * outSize.width()),
            qRound((double(g.height()) / srcBounds.height()) * outSize.height()));
        // 保持源帧宽高比，在目标区域内居中绘制
        const double srcAspect = double(srcImage.width()) / qMax(1, srcImage.height());
        const double targetAspect = double(target.width()) / qMax(1, target.height());
        QRect fitted = target;
        if (srcAspect > targetAspect)
            fitted.setHeight(qMax(1, qRound(target.width() / srcAspect)));
        else
            fitted.setWidth(qMax(1, qRound(target.height() * srcAspect)));
        fitted.moveCenter(target.center());
        painter.drawImage(fitted, srcImage);
    }
    return canvas;
}
```

合成推流时，buildComposeScreenCaptureSpec 将画布参数编码为规范字符串（包含 fps、采集区域坐标、scene_w/scene_h、每个素材的类型/源ID/几何信息、输出尺寸和编码参数），以 `__compose_scene__:` 前缀标识。StreamFFmpeg 解析该规范后，在推流循环中从各帧总线快照 YUV 帧，按 rect 信息通过 drawYuv420pContainInSlot 将每个源的帧缩放到槽位内，合成到单个 AVFrame 后送入编码管道。

## 3. 编解码与推拉流

推拉流的核心是 StreamFFmpeg 模块。输入来源通过自定义 URL Scheme 路由前缀区分：`__screen_capture__:` 走 gdigrab 直采编码，`__screen_preview__:` 和 `__camera_preview__:` 从帧总线消费 YUV 帧编码，`__compose_scene__:` 走合成管线，`__file_transcode__:` 走文件转码，无前缀的普通 URL 走 remuxLoop 流拷贝。输出统一使用 FLV 封装格式，通过 avio_open2 打开 RTMP 连接写入。

硬件加速编码通过候选列表机制实现。pickVideoEncoderCandidates 根据用户选择构建优先级列表：nvenc 对应 h264_nvenc，amf 对应 h264_amf，cpu 对应 h264_mf→libx264，auto 默认按 h264_nvenc > h264_amf > h264_mf > libx264 顺序尝试。逐个尝试打开编码器，设置 width/height/pix_fmt/time_base/gop_size（2 倍帧率）/max_b_frames=0/bit_rate（用户指定或自动估算）。NVENC 编码器额外设置 preset=p1、tune=ll、rc=cbr、zerolatency=1 共四个参数以实现最低延迟。软件 x264 编码器设置 preset=ultrafast、tune=zerolatency。当前编码器打开失败时自动回退到下一个候选，全部失败才报错。

```cpp
// 编码器选择与 NVENC 低延迟配置（streamffmpeg.cpp 节选）
const QList<VideoEncoderChoice> candidates = pickVideoEncoderCandidates(params.videoEncoder);
for (const VideoEncoderChoice& cand : candidates) {
    encCtx = avcodec_alloc_context3(cand.codec);
    encCtx->width  = params.outWidth  > 0 ? params.outWidth  : decCtx->width;
    encCtx->height = params.outHeight > 0 ? params.outHeight : decCtx->height;
    encCtx->pix_fmt   = pickEncoderPixelFormat(enc, cand.isHardware);
    encCtx->time_base  = AVRational{1, targetFps};
    encCtx->framerate  = AVRational{targetFps, 1};
    encCtx->gop_size   = targetFps * 2;
    encCtx->max_b_frames = 0;
    encCtx->bit_rate = static_cast<int64_t>(bitrateKbps) * 1000;
    // NVENC 低延迟配置
    if (codecName == "h264_nvenc") {
        av_opt_set(encCtx->priv_data, "preset", "p1", 0);
        av_opt_set(encCtx->priv_data, "tune", "ll", 0);
        av_opt_set(encCtx->priv_data, "rc", "cbr", 0);
        av_opt_set(encCtx->priv_data, "zerolatency", "1", 0);
    }
    ret = avcodec_open2(encCtx, enc, nullptr);
    if (ret >= 0) { opened = true; break; } // 成功则跳出，失败则尝试下一个候选
}
// 输出格式固定为 FLV，设置低延迟标志
avformat_alloc_output_context2(&ofmt, nullptr, "flv", outPath);
ofmt->flags |= AVFMT_FLAG_FLUSH_PACKETS;
ofmt->max_interleave_delta = 0;
```

P2P 直连模式中用户直接在 UI 中填写目标 RTMP 地址，系统以该地址作为 outputUrl 调用 streamStartPush 启动推流管道。服务端模式中，桌面端先构造 JSON 请求体（包含 app、stream、serviceMode、publisherMeta 和 sourceMeta），通过 HTTP POST 发送到 Gateway 的 /api/v1/streams/start 端点，从响应的 publishRtmp 字段提取推流地址后再启动推流。

文件推流还有 remuxLoop 流拷贝路径，使用 av_read_frame + av_interleaved_write_frame 直接转发而不经过解码和重编码，仅做封装格式转换，性能开销极低。

## 4. AI 多模态视觉分析模型接入

AI 分析功能通过 OpenAI 兼容的 Chat Completions API 接入。核心网络层封装在 AiService 类中，发送消息时先用 QImageReader 加载图片，超过 2048 像素则等比缩放，保存为 PNG 后做 base64 编码。请求体构造为标准的 vision 格式——user 消息的 content 数组包含 image_url（data:image/png;base64,...）和 text 两部分，stream 设为 true 启用流式输出。HTTP 请求设置 Content-Type 为 application/json、Authorization 为 Bearer <key>、Accept 为 text/event-stream。

```cpp
// AI 请求构造与 SSE 流式解析（aiservice.cpp 节选）
// 构造 vision 格式请求体
QJsonObject imgPart; imgPart["type"] = "image_url";
imgPart["image_url"] = QJsonObject{{"url", "data:image/png;base64," + base64Data}};
QJsonObject textPart; textPart["type"] = "text"; textPart["text"] = userMessage;
userMsg["content"] = QJsonArray{imgPart, textPart};
body["stream"] = true;  body["max_tokens"] = 1000;
// SSE 逐行解析
void AiService::onReadyRead() {
    m_streamBuffer.append(reply->readAll());
    while (true) {
        int lineEnd = m_streamBuffer.indexOf('\n');
        if (lineEnd < 0) break;
        QByteArray line = m_streamBuffer.left(lineEnd).trimmed();
        m_streamBuffer.remove(0, lineEnd + 1);
        if (!line.startsWith("data: ")) continue;
        QByteArray data = line.mid(6);
        if (data == "[DONE]") continue;
        QJsonObject obj = QJsonDocument::fromJson(data).object();
        QString chunk = obj["choices"][0]["delta"]["content"].toString();
        if (!chunk.isEmpty()) emit responseChunk(chunk);  // 逐字发射
    }
}
```

流式响应通过 readyRead 信号驱动，缓冲原始字节后逐行扫描，跳过非 data: 行和处理 [DONE] 标记。解析 JSON 的 choices[0].delta.content 提取增量文本并通过 responseChunk 信号发射。UI 层的 AiChatDialog 以 30ms 打字机定时器逐字输出到自定义绘制的 ChatBubbleWidget 聊天气泡中，气泡支持 Markdown 渲染（QTextDocument::setMarkdown），流式输出时显示闪烁光标指示。图片编码方面，通过 QImageReader 加载后若尺寸超过 2048 像素则以 KeepAspectRatio + SmoothTransformation 缩放，保存为 PNG 并做 base64 编码。

错误处理涵盖 HTTP 401（密钥无效）、429（请求超限）及通用网络错误，从响应体解析 JSON 格式的 error.message 字段获取详细错误信息。AI 配置通过 SystemSettings 以 YAML 文件持久化，API Key 密码框隐藏，主题切换时自动同步所有打开的对话窗配色。

## 5. 跨平台与打包

跨平台能力通过三层设计实现。第一层是条件编译，所有平台相关代码通过 #ifdef _WIN32 / #ifdef __linux__ 预处理器守卫隔离。典型模式包括 Windows 下 SetConsoleOutputCP(CP_UTF8) 设置控制台编码，摄像头在 Windows 上使用 dshow、Linux 上使用 v4l2，屏幕捕获在 Windows 上使用 gdigrab、Linux 上使用 x11grab 并检测 Wayland 环境。PreviewTarget 中的 NativeWindow 结构体使用条件编译携带不同的窗口句柄类型（Windows 为 HWND，macOS 为 NSView*，Linux 为 void*）。

第二层是平台特定源文件分离，用于复杂度较高的模块。流媒体后端的音频输入探测在 backend/stream_ffmpeg/src/platform/ 下分为 windows/ 和 linux/ 两个子目录，中央调度层通过预处理器条件选择编译对应实现。Windows 版本使用 WASAPI 的 COM 接口（IMMDeviceEnumerator、IAudioClient、IAudioCaptureClient）实现系统音频回环捕获；Linux 版本通过 FFmpeg 的 pulse 和 alsa 输入格式进行音频设备枚举。

第三层是 CMake 构建选项系统。后端模块通过 option 变量控制条件编译，FPLAYER_BUILD_MEDIA_DXGI 仅在 WIN32 下可用并链接 d3d11 和 dxgi 库。启用时通过 target_compile_definitions 向全项目传播 FPLAYER_WITH_SCREEN_DXGI 等编译宏，Runtime 工厂方法据此选择性实例化对应后端。Linux 下设置 RPATH 为 $ORIGIN 确保 FFmpeg 动态库的链式依赖可定位。

```cmake
# CMake 后端条件编译（backend/CMakeLists.txt）
option(FPLAYER_BUILD_MEDIA_DXGI "Build DXGI desktop capture (Windows)" ON)
if(FPLAYER_BUILD_MEDIA_DXGI AND WIN32)
    add_subdirectory(desktopcapture_dxgi)
endif()
# Runtime 层传播编译定义（runtime/CMakeLists.txt）
if(FPLAYER_BUILD_MEDIA_DXGI AND WIN32)
    target_link_libraries(${PROJECT_NAME} PUBLIC FPlayer_Backend_Desktop_Capture_Dxgi)
    target_compile_definitions(${PROJECT_NAME} PUBLIC FPLAYER_WITH_SCREEN_DXGI=1)
endif()
```

打包方面，Windows 使用 CPack 配置 NSIS 和 WiX 两种生成器，产出 .exe 安装程序和 .msi 安装包。VC++ 可再发行组件通过自动搜索 Visual Studio 安装目录或下载 vc_redist.x64.exe 纳入安装包，安装后以静默模式运行。构建流程由 package-windows.ps1 统一编排：cmake 配置 → 构建 → 安装 → cpack 打包四个阶段，产物收集到 disk/windows。打包阶段使用 windeployqt 自动收集 Qt 运行时 DLL 和插件。Linux 使用 CPack 配置 DEB 和 TGZ 生成器。
