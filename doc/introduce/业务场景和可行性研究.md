# 业务场景与可行性研究

## 1. 业务场景

FPlayer 主要面向四个业务场景。第一是教学培训，教师将屏幕内容和摄像头画面通过局域网推送到学生终端，学生用手机或电脑即可观看。第二是企业内网演示，演示者分享桌面或应用窗口给会议室同事，所有数据在内网闭环，不经过公网。第三是实验室与设备监看，多个工位或实验设备同时推流，监控端集中查看。第四是跨端内容分发，桌面端作为生产端采集推流，移动端作为消费端拉流播放。

这些场景的共同痛点是：现有商业方案依赖公网且成本高，开源命令行工具又操作门槛高，缺乏一个面向局域网、开箱即用的流媒体一体化方案。

## 2. 可行性分析

技术层面，系统基于 FFmpeg + Qt6 + ZLMediaKit + Go 构建，均为业界成熟的开源技术栈。FFmpeg 负责编解码与推拉流，ZLMediaKit 提供高性能多协议媒体分发，Go 实现轻量 HTTP 网关，Flutter 支撑跨平台移动播放。全部组件均有活跃社区和大量生产部署案例，技术风险可控。

经济层面，所有依赖均为免费开源产品，开发和部署零成本。操作层面，图形界面将推流操作控制在三步以内，便携版解压即用，非专业用户可快速上手。法规层面，系统默认纯局域网运行，数据不外传，开源协议兼容。

## 3. 竞品对比

与现有方案相比，OBS Studio 采集能力强但缺乏服务端分发和移动端播放；SRS 分发能力优秀但无采集功能和图形管理界面；FFmpeg CLI 灵活但门槛太高。FPlayer 的差异化在于三端协同一体化——桌面采集、服务端分发、移动端播放形成完整闭环，同时支持 P2P 直连和服务分发两种模式灵活切换。
