# 桌面客户端设计

## 第一部分：功能模块设计

### 1. 模块总览

桌面客户端（fplayer-ff-desktop）是整个 FPlayer 系统的流媒体生产者，负责音视频的采集、编码和推流。围绕"采集→处理→输出"的核心链路，系统划分为以下功能模块：

```
┌──────────────────────────────────────────────────────────┐
│                   桌面客户端功能模块                       │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│ 本地播放 │ 摄像头   │ 屏幕捕获  │ 推拉流   │ AI 视觉     │
│ 模块     │ 采集模块  │ 模块     │ 模块     │ 分析模块    │
├──────────┼──────────┼──────────┼──────────┼─────────────┤
│ 合成推流 │ 音频处理  │ 录制模块  │ 截图模块  │ 图片池     │
│ 模块     │ 模块     │          │          │ 模块       │
├──────────┴──────────┴──────────┴──────────┴─────────────┤
│              系统设置与主题管理                           │
└──────────────────────────────────────────────────────────┘
```

### 2. 本地播放模块

**功能描述**：支持打开本地音视频文件进行播放、暂停、进度拖动、倍速播放等操作。

**核心特性**：
- 支持 1.0x-2.0x 倍速播放，音频同步调整
- A/V 同步采用音频时钟驱动，视频帧超前 >40ms 丢弃，落后 >80ms 跳过
- Seek 操作通过 `avformat_seek_file` 实现精确定位
- 播放列表循环播放

**实现方式**：
- FFmpeg 后端：自研播放器，三线程架构（解封装线程、解码渲染线程、音频线程）
- Qt6 后端：封装 QMediaPlayer + QAudioOutput

### 3. 摄像头采集模块

**功能描述**：枚举系统中可用的摄像头设备，支持选择设备、分辨率和帧率进行实时采集和预览。

**核心特性**：
- 设备枚举（Windows：DirectShow COM API；Linux：FFmpeg v4l2）
- 动态列出每个摄像头支持的格式/分辨率/帧率组合
- 采集帧通过 swscale 统一转换为 YUV420P 格式
- 预览帧发送到 FGLWidget（OpenGL 渲染）并发布到 CameraFrameBus（供推流使用）
- 探针大小降低（32KB，200ms 分析时长）以加速设备切换

### 4. 屏幕捕获模块

**功能描述**：支持屏幕、窗口、区域的实时捕获，提供预览和帧数据输出。

**三种后端实现**：

| 后端 | 技术 | 平台 | 特点 |
|------|------|------|------|
| FFmpeg | gdigrab (Win) / x11grab (Linux) | 跨平台 | 通用兼容，性能一般 |
| DXGI | IDXGIOutputDuplication | Windows | 硬件加速，低 CPU 占用，支持 HDR 检测与跳过 |
| Qt6 | QScreenCapture | 跨平台 | API 简洁，Qt 原生集成 |

**核心特性**：
- 多显示器选择和独立区域捕获
- 光标捕获可切换（DXGI 支持 GDI 光标绘制叠加）
- 帧率可配置
- 双缩放管线：预览尺寸 + 推流目标尺寸，独立 sws 上下文

### 5. 推拉流模块

**功能描述**：支持将采集内容推送到远端服务器（推流），以及从远端拉取流进行播放和录制（拉流）。

**推流能力**：
- **直连模式**：直接推送到目标 RTMP 地址
- **服务端模式**：先向 Gateway 创建会话获取推流地址，再推流到 ZLMediaKit
- **多源推流**：文件、摄像头、屏幕、合成场景
- **文件透传**：remux 模式不解码不编码，直接流拷贝
- **文件转码**：解码后重新编码到目标码率/分辨率
- **硬件编码**：自动检测 NVIDIA/AMD/Intel 硬件编码器

**拉流能力**：
- 支持 RTMP/HTTP-FLV/HLS 拉流播放
- 支持从服务端按 streamId 自动解析拉流地址
- 拉流录制：将拉取的流同时保存到本地文件
- 拉流监视窗口：独立的播放预览窗口

**推流配置项**：
- 编码器选择（自动/指定）
- 视频码率、关键帧间隔
- 输出分辨率和帧率
- 宽高比策略（保持/拉伸/裁剪）
- 音频输入源选择（系统音频/MIC/静音）
- 音频输出监听

### 6. 合成推流模块（Compose Mode）

**功能描述**：支持将多个采集源（视频文件、摄像头、屏幕）组合到一个画布中，合成后统一推流。

**核心特性**：
- 多源 MDI 子窗口布局管理，支持自由拖拽和缩放
- Z 轴层级管理（置顶/置底）
- 各源独立控制（播放/暂停/素材替换）
- 合成画布尺寸可配置
- 支持宽高比保持和裁剪模式
- 合成的 YUV 帧通过 ScreenFrameBus 的 compose 通道发布

**数据流**：
```
多源采集 → 各源独立 FGLWidget 渲染 → ScreenFrameBus 多通道
→ pushComposeSceneLoop() YUV 合成 → 编码 → RTMP 推流
```

### 7. 音频处理模块

**功能描述**：管理音频输入采集和输出监听。

**核心特性**：
- WASAPI Loopback（Windows）：捕获系统音频输出，无需虚拟声卡
- 麦克风输入采集
- Planar 格式音频混音管线（`audio_pipeline.h`）
- FIFO 缓冲区平滑音视频同步
- swresample 重采样（采样率、声道布局转换）

### 8. 录制模块

**功能描述**：将采集内容或拉流内容保存为本地视频文件。

**核心特性**：
- 主窗口录制：录制当前捕获源的内容
- 拉流录制：录制从远端拉取的流
- 录制时长计时器显示

### 9. AI 视觉分析模块

**功能描述**：集成 OpenAI 兼容的 Chat Completions API，对截图或图片进行 AI 分析。

**核心特性**：
- 多模态请求（图片 + 文本消息）
- SSE（Server-Sent Events）流式响应解析
- 打字机效果的逐字展示
- 图片自动缩放（最大 2048px）和 Base64 编码
- 可配置的 API 端点、密钥、模型
- 聊天气泡式交互界面，支持自定义颜色

### 10. 图片池模块

**功能描述**：管理截图和本地图片的浏览、排序和操作。

**核心特性**：
- QFileSystemWatcher 实时监控图片目录
- 缩略图网格浏览（QListWidget 图标模式）
- 多种排序方式（名称/日期/大小，升序/降序）
- 缩略图 LRU 缓存
- 图片查看器：全屏浏览、键盘导航、滚轮缩放
- 右键菜单：打开、复制、删除、重命名、AI 分析

### 11. 系统设置与主题管理

**功能描述**：持久化应用设置和主题切换。

**核心特性**：
- YAML 格式的配置文件持久化
- 深色/浅色主题切换，跟随系统
- 自定义主题色
- 设置项：截图/录制目录、推拉流历史、Gateway URL、AI 配置、屏幕捕获后端、关闭行为

## 第二部分：技术选型

### 1. 技术栈概览

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| 编程语言 | C++17 | — | 高性能、跨平台、与 FFmpeg/Qt 深度集成 |
| UI 框架 | Qt 6.10 | 6.10.2 | 成熟跨平台 GUI、信号槽机制、丰富的多媒体 API |
| 视频渲染 | OpenGL | 2.1+ | YUV420P 硬件纹理渲染、自定义 Shader、高性能 |
| 媒体处理 | FFmpeg | 8.1 | 全格式编解码、流媒体协议、硬件编码支持 |
| 构建系统 | CMake | 3.15+ | 跨平台构建、模块化编译、CPack 打包 |
| 日志库 | Logger | v1.1.4 | 轻量、线程安全、文件日志 |
| 配置解析 | yaml-tool | v1.0.2 | YAML 序列化/反序列化 |
| 包管理 | CPM.cmake | — | CMake 的轻量级包管理器 |
| 安装包 | NSIS / WiX / DEB | — | Windows 安装包 / Linux DEB 包 |

### 2. 选型分析

#### 2.1 为什么选择 C++17

- FFmpeg 和 Qt 均以 C/C++ 为原生接口，C++ 调用无 FFI 开销
- 音视频处理涉及大量内存操作和实时计算，C++ 提供零成本抽象和确定性资源管理
- 跨平台编译（MSVC、MinGW、GCC）支持良好
- C++17 的结构化绑定、if constexpr、string_view 等特性提升代码质量

#### 2.2 为什么选择 Qt 6.10

- 一套代码同时支持 Windows 和 Linux 的 GUI 开发
- QOpenGLWidget 提供原生 OpenGL 渲染上下文，适合视频渲染
- QMediaPlayer / QCamera / QScreenCapture 提供备用的媒体后端
- 信号槽机制天然适合事件驱动的多媒体应用
- Qt Designer 支持 UI 的可视化设计
- 成熟的国际化、主题、系统托盘等功能

#### 2.3 为什么选择 FFmpeg 8.1

- 业界标准的音视频处理库，支持所有主流编码格式和流媒体协议
- libavcodec 支持 NVIDIA/AMD/Intel 硬件编解码器
- libavformat 支持 RTMP/SRT/RTSP/HLS 等流媒体协议
- libavdevice 支持 dshow/v4l2/gdigrab/x11grab 等采集设备
- libswscale 提供高效的颜色空间转换和缩放
- libavfilter 支持丰富的音视频滤镜

#### 2.4 为什么提供多后端

- Qt6 后端：API 简洁、与 Qt 生态无缝集成、适合快速开发和简单场景
- FFmpeg 后端：功能完整、性能优化、支持硬件编码、适合高性能场景
- DXGI 后端：Windows 下最优的屏幕捕获方案，CPU 占用低、延迟最小

多后端设计允许用户根据场景和平台选择最优方案，同时保持了系统的灵活性。

#### 2.5 为什么选择 CMake + CPM.cmake

- CMake 是 C++ 生态的事实标准构建系统
- CPM.cmake 提供类似 npm/cargo 的依赖管理体验，无需手动管理预编译库
- CPack 集成可一键生成 Windows 安装包和 Linux DEB 包

```
│  ScreenFrameBus / CameraFrameBus (帧总线)   │
└─────────────────────────────────────────────┘
```

### 2. 模块依赖规则

模块之间存在严格的依赖方向约束：

1. **api 层零依赖**：不依赖任何后端实现，仅依赖 Qt::Core/Qt::Gui 和 Logger
2. **common 层单向依赖**：仅依赖 Qt::OpenGL 和 Logger，不依赖 api 层
3. **backend 层实现 api 接口**：每个后端模块依赖 api（接口定义）和 common（FGLWidget、FrameBus）
4. **runtime 层是唯一的组装点**：runtime 依赖所有后端模块，是唯一知道所有后端存在的模块
5. **service 层不直接接触后端**：service 仅依赖 runtime（通过 api 接口操作）和 common
6. **widget 层依赖 service**：UI 层通过 Service 类操作业务，不直接访问 runtime 或 backend

这种严格的依赖方向保证了：
- 后端可以独立替换而无需修改上层代码
- 编译时各模块可以并行编译
- 新增后端只需实现 api 接口并在 runtime 注册即可

### 3. 策略模式与工厂模式

Runtime 类是整个后端的工厂入口：

```cpp
// 根据 MediaBackendType 创建对应后端实例
std::shared_ptr<IPlayer>    createPlayer();
std::shared_ptr<ICamera>    createCamera();
std::shared_ptr<IScreenCapture> createScreenCapture();
std::shared_ptr<IStream>    createStream();
```

`createScreenCapture()` 的路由逻辑体现了策略选择：
- `MediaBackendType::Qt6` → ScreenCaptureQt6
- `MediaBackendType::FFmpeg` → ScreenCaptureFFmpeg (gdigrab/x11grab)
- `MediaBackendType::Dxgi` → ScreenCaptureDxgi (带 FFmpeg 回退)

### 4. PreviewTarget 桥接模式

由于 api 层不能包含 Qt 的 Widget 依赖（保持接口纯净），而不同后端需要不同类型的渲染控件（Qt6 后端需要 QVideoWidget，FFmpeg 后端需要 FGLWidget），系统设计了 `PreviewTarget` 桥接结构：

```cpp
struct PreviewTarget {
    NativeWindow nativeWindow;  // 平台原生窗口句柄 (HWND/NSView)
    void* backend_hint;        // 后端特定控件指针
    // Qt6 后端 -> QVideoWidget*
    // FFmpeg 后端 -> FGLWidget*
};
```

FVideoView 作为视频渲染容器，内部根据当前后端类型动态创建对应的子控件，通过 `backend_hint` 传递给后端使用。这使得 api 层保持了对 Qt Widget 的无依赖。

### 5. 帧总线模式

ScreenFrameBus 和 CameraFrameBus 采用单例、多通道、线程安全的生产者-消费者模式：

```
生产者 (捕获线程)                消费者 (推流线程)
     │                                │
     │ publish(frame, sourceId)       │ snapshotIfNew(sourceId, &serial)
     ▼                                ▼
┌─────────────────────────────────────────┐
│          FrameBus (Singleton)            │
│  QMap<int, FrameChannel> channels;      │
│  QMutex mutex;                          │
├─────────────────────────────────────────┤
│  FrameChannel:                           │
│    QByteArray y/u/v data;              │
│    int serial;  // 递增序列号           │
│    int width, height;                  │
└─────────────────────────────────────────┘
```

**设计要点**：
- 序列号机制：消费者通过 `snapshotIfNew(sourceId, &serial)` 仅获取新的帧，避免重复编码
- 零拷贝优化：通过 QByteArray 的隐式共享（COW）减少内存拷贝
- 多通道隔离：不同 sourceId 的数据完全隔离，合成模式可同时读取多个通道

### 6. 推流 URL Scheme 路由模式

StreamFFmpeg 使用自定义 URL Scheme 统一多源推流接口：

```
IStream::startPush(inputUrl, outputUrl)
    │
    ▼
parsePushInputRoute(inputUrl)
    │
    ├── "__compose_scene__:..."  → pushComposeSceneLoop()
    ├── "__screen_capture__:..." → pushScreenLoop()
    ├── "__screen_preview__:..." → pushScreenPreviewLoop()
    ├── "__camera_capture__:..." → pushCameraLoop()
    ├── "__camera_preview__:..." → pushCameraPreviewLoop()
    ├── "__file_transcode__:..." → transcodeFileLoop()
    ├── "__file_preview__:..."   → use ScreenFrameBus frames
    └── default (file path)      → remuxLoop() (stream copy)
```

这种设计将多个推流策略统一在一个简单的 API 接口下，新增推流策略只需添加新的 URL Scheme 和处理循环。

### 8. CMake 构建体系

#### 8.1 模块化构建

每个源代码模块编译为独立的共享库（DLL/SO），最终链接为单一可执行文件：

```
api/           → FPlayer_Api.dll
common/        → FPlayer_Common.dll
backend/media_ffmpeg/  → FPlayer_Backend_Media_FFmpeg.dll
backend/media_qt6/     → FPlayer_Backend_Media_Qt6.dll
backend/stream_ffmpeg/ → FPlayer_Backend_Stream_FFmpeg.dll
backend/desktopcapture_dxgi/ → FPlayer_Backend_Desktop_Capture_Dxgi.dll
runtime/       → FPlayer_Runtime.dll
service/       → FPlayer_Service.dll
widget/        → FPlayer_Widget.dll
app/           → FPlayer.exe (可执行文件)
```

#### 8.2 标准化模块宏

项目定义了 `add_standard_module()` CMake 宏，自动化处理：
- 源文件收集
- 导出头文件生成（`global_template.h.in`）
- MOC/UIC/RCC Qt 预处理
- 包含目录和链接库设置

#### 8.3 后端条件编译

通过 CMake 选项控制后端的启用/禁用：
- `FPLAYER_BUILD_MEDIA_FFMPEG` — 是否编译 FFmpeg 媒体后端
- `FPLAYER_BUILD_MEDIA_QT6` — 是否编译 Qt6 媒体后端
- `FPLAYER_BUILD_STREAM_FFMPEG` — 是否编译 FFmpeg 推流后端
- `FPLAYER_BUILD_DESKTOPCAPTURE_DXGI` — 是否编译 DXGI 捕获后端

#### 8.4 CPack 打包

- **Windows**：NSIS 安装包（.exe）+ WiX 安装包（.msi）
- **Linux**：DEB 包 + TGZ 压缩包
- 自动部署 Qt 运行时 DLL（windeployqt）
- VC++ Redist 自动下载和捆绑

### 9. 跨平台设计

#### 9.1 平台特定代码隔离

- **Windows 音频**：`backend/stream_ffmpeg/src/platform/windows/wasapiloopbackcapture.h/.cpp`
- **Windows 摄像头枚举**：CameraInfoFetcher 中使用 DirectShow COM API
- **Linux 摄像头**：FFmpeg v4l2 设备列表，默认格式预设
- **屏幕捕获**：Windows 使用 gdigrab 或 DXGI，Linux 使用 x11grab

#### 9.2 NativeWindow 跨平台抽象

```cpp
struct NativeWindow {
#ifdef _WIN32
    HWND hwnd;
#elif __linux__
    Window xid;
#endif
};
```
