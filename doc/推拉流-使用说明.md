# 推拉流使用说明

## 1. 功能入口

在主窗口顶部菜单栏中，点击：

- `推拉流` -> `推流`
- `推拉流` -> `拉流`

会弹出对应的配置窗口。

---

## 2. 推流使用

## 2.1 配置项说明

- `协议模板`：快速填充输出地址（RTMP / RTSP / SRT）
- `输出`：推送目标地址
- `推送到服务端`：开启后先向 service 创建会话，再自动使用 service 返回的 RTMP 地址推流
- `服务地址 / 服务 app / 服务 stream / 服务类型`：仅在“推送到服务端”场景使用
- `帧率`：`跟随当前` 或手动指定
- `尺寸`：`跟随当前`、预设分辨率、或手动输入 `WxH`
- `保持宽高比`：按源分辨率比例自动调整目标尺寸
- `码率`：`跟随当前` 或手动指定（kbps）
- `视频编码器`：`自动（优先NVENC/AMF）` / `CPU（x264）` / `NVIDIA NVENC` / `AMD AMF`
- `声音来源`：可选 `关闭声音` / `系统声音（实验）` / 枚举到的本机音频输入设备

常见示例：

- RTMP：`rtmp://127.0.0.1:1935/live/stream`
- RTSP：`rtsp://127.0.0.1:8554/live/stream`
- SRT：`srt://127.0.0.1:8890?mode=caller`

服务分发模式（建议用于一对多/多对多）：

- 服务地址：以 `fplayer-ff-service` 运行后生成的 `run/runtime.json` 中 `gateway.url` 为准
- 服务类型：`广播分发` 或 `HTTP-FLV 转换`
- 推流端在开始推流前会向服务端上报元信息（场景、编码参数、推流端 IP 等）
- 服务端返回可拉流地址，界面会显示 `HTTP-FLV` 字段便于复制
- 若 service UI 显示“正在启动服务...”，请等待“服务已就绪”后再在 desktop 点击开始推流
- 当推流模式选择“推送服务端”时，推流窗口会在日志区前显示红色提示：分辨率和帧率请勿设置过高，建议不要超过 `1920x1080 & 60fps`

## 2.2 操作流程

1. 点击 `推拉流` -> `推流`
2. 先确认 `fplayer-ff-service` 已启动，并记录 `run/runtime.json` 里的 `gateway.url`
3. 根据当前模式确认来源（文件/摄像头/屏幕）
4. 选择协议模板（可选）
5. 填写输出地址与推流参数
6. 点击 `开始推流`（窗口不会关闭）
7. 如需停止，点击窗口内 `停止推流`

补充（主预览底部按钮）：

- `截图`：优先按原始帧分辨率导出（摄像头/屏幕），拿不到原帧时回退窗口抓图。
- `录制`：按源链路录制（不受当前预览窗口缩放影响）。
- `设置`：打开系统设置页，可配置截图/录制保存目录。

## 2.3 状态与日志

窗口内提供：

- `状态`：运行中 / 已停止 + 退出码（与程序内 FFmpeg 库返回的错误码一致，成功为 `0`）
- `日志`：应用侧记录的最近状态与错误摘要（自动刷新）
  - 服务端模式下，日志区前会显示负载风险提示（红字），用于提醒避免高分辨率/高帧率导致服务端压力过大
  - 启动后会打印“最终生效参数”，用于核对实际输出（输入尺寸、输出尺寸、FPS、码率、模式）
  - 会打印当前视频编码器，例如：`编码器=h264_nvenc（硬件）`、`编码器=h264_amf（硬件）`、`编码器=libx264（软件）`
  - 屏幕模式会额外打印来源链路：
    - `来源=DXGI预览帧`：屏幕视频来自当前 DXGI 预览帧（推荐）
    - `采集区域=...`：来自 FFmpeg `gdigrab` 采集链路
  - 屏幕模式“当前参数”会显示当前屏幕后端：`DXGI` / `FFmpeg(gdigrab)`

## 2.4 组合模式

- **入口**：在模式菜单选择「组合模式」（与摄像头/文件/屏幕并列）。展开后左侧可添加文件、摄像头、屏幕等来源，中间为画布预览（可拖动、叠放顺序、裁剪等），底部参数随当前选中来源切换。
- **输出内容**：推流画面为 **后台按场景合成后的视频**（多源 YUV 合成再编码），与预览布局、层级一致；**不是**对预览窗口截图推流。
- **分辨率与比例**：推流对话框中的「尺寸」若与左侧画布比例不一致，编码时会 **等比缩放画布并加黑边** 以适配输出分辨率，避免画面被横向或纵向拉伸；若希望铺满且无黑边，请选择与当前画布比例一致的输出尺寸（例如画布 16:9 时选 1920x1080）。
- **画布比例**：左侧可选择固定宽高比，主窗口可随比例调整；素材可独立是否锁定宽高比缩放。
- **播放/暂停**：**只有**主窗口底部工具栏一组播放/暂停图标；在组合模式下，该图标表示 **当前选中素材**（左侧列表或画布点击）自己的播放/暂停状态，切换选中行时图标会随之切换；不会一键暂停全部素材。
- **切换到其他模式**：会 **暂停/停止** 组合内所有素材的采集与播放，并收起组合画布（素材列表与子窗口保留，再次进入组合模式可继续编辑；不会一直在后台跑 DXGI/摄像头/文件解码）。
- **摄像头资源释放（模式切换）**：
  - 从“摄像头模式”切到“组合模式”时，会先释放主预览摄像头占用，再启用组合内摄像头素材，减少设备句柄冲突导致的黑屏/无画面。
  - 从“组合模式”切回其他模式时，会释放组合内摄像头占用；再次进入组合模式会自动重建并恢复相机素材绑定。
- **多路屏幕**：多路屏幕素材按各自播放状态独立运行，不再互相自动暂停；切换某一路的显示器会同步更新该素材名称与参数。
- **多路摄像头**：多路摄像头素材按 `sourceId` 独立发布帧，推流端不会再出现“两个摄像头素材互相闪现切换”。
- **素材命名**：左侧列表在设备切换后会更新名称，并附加短 `sourceId`（如 `[1a2b3c4d]`）便于区分同类素材。
- **音频**：组合场景推流已支持 `audio_in / audio_out` 音频链路（含回退与混音策略），与屏幕/摄像头推流保持同类解耦方案。
- **排查**：若需分析合成或编码问题，可让开发者在 `StreamFFmpeg::pushComposeSceneLoop`、DXGI/摄像头等位置 **临时打开** 已注释的诊断日志。

## 2.5 预览暂停后开始推流（单路：文件 / 摄像头 / 屏幕）

- **屏幕（DXGI 预览帧）与摄像头（预览帧推流）**：若在主界面先 **暂停预览** 再点推流，拉流端应能持续收到 **定格在暂停瞬间的画面**（推流侧会按帧率重复最后一帧），而不会长时间卡在加载中。
- **文件模式**：默认 **直推 copy** 或 **独立文件转码** 与预览里的播放器 **不是同一条管线**，推流内容与「预览是否暂停、播到哪一帧」**不一定一致**；若你期望推流画面与预览暂停时完全一致，需使用组合等能走预览帧总线的能力（详见开发文档说明）。

## 3. 拉流使用（监视窗口）

## 3.1 配置项说明

- `协议模板`：快速生成地址前缀（RTMP / RTSP / SRT / UDP）
- `推流码`：与协议模板拼接生成拉流地址
- `拉流地址`：只读标签（不可编辑），右侧可一键复制
- 拉流窗口默认行为：启动后自动打开预览窗口，预览窗口内可直接截图/录制
- `开始拉流 / 结束拉流`：按钮互斥（开始前禁用结束；开始后禁用开始）

常见示例：

- 拉流监听：`rtmp://0.0.0.0:1935/live/stream001`
- 推流端发布（局域网）：`rtmp://192.168.x.x:1935/live/stream001`

## 3.2 操作流程

1. 点击 `推拉流` -> `拉流` 打开**非模态**监视窗口（不会阻塞主界面）
2. 选择协议模板并填写推流码，按需复制生成的拉流地址
3. 点击 `开始拉流`
4. 成功后自动弹出独立 `拉流预览` 窗口
5. 如需录制，在预览窗口点击 `录制`
6. 如需停止，点击监视窗口 `结束拉流`（会联动关闭预览）

## 3.3 服务端拉流（按 streamId 自动解析）

若你使用 service 分发链路，推荐：

1. 先确认 service 已就绪，读取 `run/runtime.json` 的 `gateway.url`
2. 在拉流窗口选择“从服务端按 streamId 自动解析”
3. 服务地址填写 `gateway.url`
4. 输入 `streamId`，优先协议选择 `HTTP-FLV`
5. 点击 `解析地址` 或直接 `开始拉流`

## 3.4 拉流预览窗口

- 预览窗口底部工具栏：`暂停`、`刷新`、`截图(80px)`、`录制(80px)`、`设置`、`音量(0~200%)`、实时百分比
- 预览采用 **进程内总线**（`pull_preview`）显示，不再通过播放器二次网络拉流
- 音量支持放大（>100%）并带软限幅，避免明显爆音
- 预览窗口内录制采用“拉流落盘模式”，会写入音频轨（前提是上游流携带音频）
- 录制日志会输出开始/结束、落盘路径、文件是否存在与大小，便于排查
- 录制按钮右侧显示“拉流总时长”（从拉流启动开始计时；暂停预览不影响计时；停止拉流后清零）
- 截图/录制开始与结束使用更明显的顶部气泡提示（非阻断）
- 点击预览窗口右上角关闭时，会弹确认：确认后停止拉流并关闭预览；取消则不关闭
- 监视窗口也仅保留右上角关闭，行为与原“关闭按钮”一致（运行中会先确认并停止任务）
- 与监视窗口双向联动

## 4. 历史记录

推流和拉流都支持最近地址记录（持久化）：

- 最近推流输入/输出
- 最近拉流输入

每项最多保留 8 条，最新项在最前面。

并且以下配置会持久化到 `system_settings.yaml`（可执行程序同目录）：

- 截图/录制保存目录
- 推流服务端参数（gateway/app/stream）
- 拉流服务端参数（gateway/app/stream）
- 推流高级参数（路由模式、服务类型、协议模板、FPS、尺寸、码率、编码器、音频选择、保持宽高比）

## 5. 常见问题

## 5.1 屏幕模式出现扭曲/错位（尤其在 HDR 开启时）

可能表现：

- DXGI 预览时画面扭曲、闪烁或不稳定
- 日志提示 `skip unsupported duplication format=R16G16B16A16_FLOAT`

原因：

- 系统 HDR/高级色彩开启后，DXGI 可能返回浮点格式帧；当前策略会跳过这类不支持帧以保证进程稳定。

处理建议：

1. 打开“系统设置”并将“屏幕采集后端”切换为 `FFmpeg（gdigrab）`
2. 或手动关闭系统 HDR 后继续使用 `DXGI（默认）`
3. 在屏幕模式下若检测到 HDR，会显示提示：可切换 FFmpeg 后端（但可能造成鼠标光标闪烁）

## 5.0 推流前置条件

- 若提示 `stream not initialized`，通常是构建时未启用网络 FFmpeg 后端
- 请确认 CMake 选项：`FPLAYER_BUILD_STREAM_FFMPEG=ON`
- 重新 Configure + Build 后再运行

## 5.2 点击确定后提示启动失败

可能原因：

- 程序目录下 **缺少 FFmpeg 运行库**（`avformat-*.dll`、`avcodec-*.dll` 等），或安装不完整
- 输入地址不可达、协议/格式不被当前编译的 FFmpeg 支持
- 输出地址不可写、媒体服务器拒绝连接或路径错误

建议：

- 确认与主程序一同发布的 `3rd/ffmpeg_*` 对应 **bin** 中 DLL 已复制到可执行文件目录（与正常播放、采集功能一致）
- 检查地址、端口、防火墙与服务器是否已启动

## 5.3 推流成功但播放器看不到画面

建议排查：

- 推流协议与播放端协议是否一致
- 媒体服务器是否正常（如 rtmp/rtsp 服务）
- 目标 URL 路径是否正确

## 5.4 服务端模式报 `Failed to fetch`

建议排查：

- service UI 是否已显示“服务已就绪”
- `fplayer-ff-service/run/runtime.json` 是否存在，且其中 `gateway.url` 可访问
- desktop 中“服务地址”是否填写了该 `gateway.url`（不要手填固定 `:9000`）
- 查看 service 日志：`logs/gateway.err.log` / `logs/ui.err.log`

## 5.5 拉流预览无画面

建议排查：

- 输入流是否可用（先用 ffplay/vlc 验证）
- 网络是否连通（跨设备场景）
- 监视窗口日志中是否出现：
  - `预览解码器已启用`
  - `检测到上游推流连接`
  - `已切换为进程内预览总线（pull_preview）`
- 若以上均出现仍无画面，优先反馈拉流日志中的每秒统计与错误码

## 5.6 屏幕推流看起来忽快忽慢

建议排查顺序：

1. 先用 `跟随当前` 的 FPS/码率
2. 若机器负载高，降低 FPS（如 60 -> 30）
3. 码率过低会“糊”，可提高到合适区间（例如 1080p60 常见 8~16Mbps）
4. 对比日志里的“采集尺寸/输出尺寸/FPS/码率”是否符合预期

## 5.7 想确认是缩放还是裁剪

查看推流日志中的两组值：

- `采集区域=... WxH`
- `输出=... WxH`

当采集尺寸与输出尺寸不同且画面完整时，表示为“整屏采集后缩放输出”。

## 5.8 推流音频说明（屏幕/摄像头/组合）

- 支持 `audio_in / audio_out` 单路或双路采集（失败自动降级）
- 非文件推流统一采用“视频线程 + 音频线程”解耦
- 音频发送采用固定节拍与补静音策略，降低“慢半拍/断续”风险
- 组合模式同样支持音频链路，不再默认无声

## 5.9 硬件编码器说明（NVENC / AMF）

- 选择 `自动` 时，系统按 `NVENC -> AMF -> CPU` 顺序自动回退
- 若手动选择 `NVIDIA NVENC` 或 `AMD AMF`，但本机 FFmpeg 未编译该编码器或驱动不可用，会启动失败并提示编码器不可用
- 建议通过日志中的 `编码器=...（硬件/软件）` 确认是否真正走了硬件编码
- 组合推流路径已修复编码器参数兼容：不会再向 `h264_nvenc/h264_amf` 传入 x264 风格 `superfast/zerolatency`，若日志中仍出现 `Unable to parse "preset/tune"` 请反馈完整日志

## 5.10 Release 默认暂停（Debug 正常）

可能表现：

- 调试运行时进入模式默认播放，Release 包启动后同样路径默认处于暂停

原因：

- 典型是“播放状态标志与实际启动状态不同步”导致的时序问题（优化级别不同会放大表现差异）
- 当前版本已修复 `CameraQt6` 默认播放状态同步问题

建议：

1. 使用包含本次修复的最新构建重新打包
2. 若仍出现该现象，请附上完整日志（模式切换 -> 添加素材 -> 开始推流全过程）

## 5.11 摄像头模式切到组合模式后，相机素材无画面

建议排查：

1. 使用最新版本（已加入模式切换时的摄像头释放与重建逻辑）
2. 切换顺序建议：先进入组合模式再选择相机素材设备
3. 若仍偶发无画面，可先切到其他模式再切回组合模式触发素材重建
4. 提交日志时附带操作顺序：摄像头模式 -> 组合模式 -> 选择设备 -> 是否恢复
