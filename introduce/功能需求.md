# 功能需求

## 1. 桌面客户端

桌面客户端的核心职责是音视频采集、编码和推流。采集方面支持本地文件播放、摄像头和屏幕捕获三种输入源，三者可单独推流，也可组合到同一画布合成推流。推流分为两种模式：P2P 直连时手动填写目标地址，提供协议模板辅助；服务端模式下填写 Gateway 地址和 app/stream 即可自动创建会话并获取推流地址。拉流播放同样支持 P2P 直拉和服务端解析，采用监视窗口加独立预览窗口联动设计。此外提供图池管理（相册式浏览截图）和 AI 视觉分析（OpenAI 兼容接口的 SSE 流式对话）。

## 2. 流媒体服务端

服务端是控制中枢与分发核心，架构分为三层。数据面由 ZLMediaKit 承担，负责 RTMP 推流接入和 HTTP-FLV、HLS、RTSP 等多协议分发。控制面由 Go 编写的 Gateway 承担，提供 RESTful API 管理流的创建、查询、停止和按名称解析，创建接口幂等（同名重复请求返回已有流），地址编排模块智能生成播放地址并支持公网代理覆盖。

管理面提供两种形态：Electron UI 是图形化桌面窗口，按需启动内核，支持地址一键复制、日志监视和主题切换；Kernel Console 是命令行版本，适合无图形界面的服务器部署。启动编排自动完成端口探测、配置生成、子进程拉起和健康检查，端口冲突自动切换重试。运行信息写入 runtime.json 供外部读取。

## 3. 移动播放端

移动端基于 Flutter 和 media_kit，支持 HLS、HTTP-FLV、RTMP 播放，提供两种接入方式：填写 Gateway+app+stream 自动解析地址，或直接输入完整 URL。覆盖 Android、Windows 和 Web 平台。
