# 功能需求

> 对应 UML 用例图：[doc/UML-用例图.drawio](../doc/UML-用例图.drawio)（参与者：桌面用户、安卓用户、FPlayer-Service 服务端、AI 多模态服务）

## 1. 桌面客户端

桌面客户端的核心职责是音视频采集、编码和推流。采集方面支持本地文件播放、摄像头和屏幕捕获三种输入源，三者可单独推流，也可组合到同一画布合成推流。本地文件播放由 FFmpeg/Qt6 后端负责解封装与解码，输出 YUV 帧供渲染或后续编码；摄像头采集支持枚举系统设备列表（含虚拟摄像头），使用 30 秒 TTL 缓存加速模式切换；屏幕捕获支持全屏或区域截取，4K 下通过预览与推流双路缩放合并为一次 `sws_scale`，CPU 占用降低 30-40%。这三种采集方式与推流之间是 `«include»` 关系——推流必须以其中至少一种为输入源。

推流分为两种模式。P2P 直连时手动填写目标地址，提供 RTMP/SRT/RTSP 协议模板辅助填写；服务端模式下填写 Gateway 地址和 app/stream 即可自动创建会话并获取推流地址（`«extend»` 了 P2P 推流，用服务端地址编排替代手动填写）。编码链路针对低延迟场景做了专项优化，NVENC 采用 p1 预设 + ll + cbr + zerolatency + rc-lookahead=0，AMF 采用 ultralowlatency + speed + cbr，x264 采用 ultrafast + zerolatency，端到端延迟降低 30-50%。在此基础上，组合模式推流（`«extend»` 推流）允许将摄像头、屏幕、本地文件等多源素材拖入同一画布自由布局，支持拖拽缩放与可见性控制，设备冲突自动检测与恢复，后台通过 YUV 合成编码实现多源混流，组合链路中音视频解耦处理，底部播放键随当前选中素材切换状态。

拉流播放同样支持 P2P 直拉和服务端解析两种方式，采用监视窗口加独立预览窗口联动设计。拉流过程中提供录制功能（`«extend»` 拉流），独立录制链路不影响播放，录制时长实时显示。推拉流的编码器选择、码率、分辨率、帧率等参数均可在设置页面详细配置。

此外桌面客户端还提供图池管理功能——以相册式独立窗体浏览截图目录，支持缩略图网格展示、按日期/名称/大小排序、大图预览（键盘导航与缩放）、右键菜单（打开/复制/重命名/删除），以及 QFileSystemWatcher 自动同步与手动刷新。在此之上扩展了 AI 视觉分析功能（`«extend»` 图池），右键图片可发起 AI 识别对话，系统自动发送分析请求，通过 OpenAI 兼容的多模态视觉模型 API 进行图片识别，采用 SSE 流式逐字输出配合闪烁光标，配置项包括 API 地址、密钥和模型名称。系统设置方面支持深色/浅色主题切换、自定义主题色、AI 聊天气泡颜色、字体字号，以及截图/录制目录、采集后端、关闭行为等通用偏好。

## 2. 流媒体服务端

服务端是控制中枢与分发核心，架构分为三层。数据面由 ZLMediaKit 承担，负责 RTMP 推流接入和 HTTP-FLV、HLS、RTSP 等多协议分发，提供高性能流媒体转发能力。控制面由 Go 编写的 Gateway 承担，提供 RESTful API 管理流的创建、查询、停止和按名称解析，创建接口幂等（同名重复请求返回已有流，避免资源泄漏），地址编排模块智能生成播放地址并支持公网代理覆盖，同时维护 `runtime.json` 文件供客户端读取 Gateway URL 和服务状态。

管理面提供两种形态：Electron UI 是图形化桌面窗口，按需启动内核，支持地址一键复制、日志监视和主题切换；Kernel Console 是命令行版本，适合无图形界面的服务器部署。启动编排自动完成端口探测、配置生成、子进程拉起和健康检查，端口冲突自动切换重试。

在三端协同链路中，桌面端负责采集与推流，Service 作为中枢完成流地址解析与统一分发（`«extend»` 了推流链路），移动端或另一桌面端发起拉流播放，形成完整的"生产 → 调度 → 消费"闭环。

## 3. 移动播放端

移动端基于 Flutter 和 media_kit，仅承担播放消费角色，不提供采集推流能力。播放格式支持 HLS、HTTP-FLV、RTMP，提供两种接入方式：填写 Gateway + app + stream 自动解析播放地址（与服务端协同），或直接输入完整 URL（独立使用）。覆盖 Android、Windows 和 Web 平台。在三端协同场景下，移动用户作为独立的拉流消费方，通过服务端解析获取桌面端推送的流地址并实时播放。
